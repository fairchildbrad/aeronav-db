<acceptance_criteria>
## AC-1: Sticky attachment
Given an identity X that holds both NASR site key K and OurAirports id O
When, in a later cycle, NASR record K and OurAirports row O share no code (e.g. NASR says DJT/KDJT, OurAirports still says PBI/KPBI) but are within SAME_AIRPORT_NM and pass the country gate
Then O stays attached to K's entity: X keeps one id, NASR's FAA/ICAO codes, and O's IATA code. No id is minted.
Not sticky if O now shares a code with a different NASR record, or is out of range. The normal rules then apply.

## AC-2: Every archive format reads to the same rows
Given an archived cycle in format a, b or c
Then the reader returns APT rows with SITE_NO, SITE_TYPE_CODE, ARPT_ID, ICAO_ID, ARPT_NAME, ARPT_STATUS, LAT_DECIMAL, LONG_DECIMAL, COUNTRY_CODE.
Given a cycle that ships both the fixed-width text and CSV
Then the two parses yield identical identity observations. Every difference is listed in the SUMMARY and either fixed or explained.
A field that the legacy format lacks is never invented. If COUNTRY_CODE is absent, a mapping from a legacy field is used only if the overlap cycle validates it 100%; otherwise the field is NULL (the gate then fails safe).

## AC-3: Reproducible, resumable backfill
`python -m aeronav_db.backfill --from 2020-03-26 --to CYCLE --cache DIR --out seed.sqlite3`
- enumerates AIRAC cycles;
- caches each cycle's APT member and the OurAirports snapshot (the last commit before the cycle date, recording its sha);
- applies cycles in order and writes a schema-3, identity-only file (airports table empty).
Running it twice gives identical identity tables. An interrupted run resumes from the cache. A cycle missing from the archive is skipped and recorded, never fabricated.

## AC-4: The seed is chain-valid
- The seed passes `check_identity` (0 FAA/ICAO violations) and is accepted by `build --previous-db`.
- `check_chain` passes between every consecutive pair of cycle states during the replay.
- Metadata: history_start = first NASR cycle; history_start_ourairports = first cycle with an OurAirports snapshot; backfill_sources = per-cycle NASR URL + sha256 of the APT member actually parsed + OurAirports commit sha (lineage); skipped_cycles. <!-- audit-added --> The seed's own sha256 is recorded in the SUMMARY; 02-02 may chain only from a seed that a cache re-run reproduces byte-identically in its identity tables.

<!-- audit-added -->
## AC-6: Anomaly guard (a parser slip must not mint thousands of ids)
Given any replayed cycle after the first
When it mints more than 2% of its NASR observations, or closes more than 2% of open presence intervals
Then the replay stops with the cycle's counts, unless that cycle is listed in a checked-in allowlist with a written reason. Format-boundary cycles (a→b, b→c) are reported explicitly in the SUMMARY.

## AC-5: History report
The backfill writes a report:
- per-cycle counts (minted, matched by basis, closed presence, convergences);
- every alias with its cycle;
- non-ISO COUNTRY_CODE values per cycle;
- every (iata, code, date) held by more than one present airport over the whole history (cv-aviation's request).
The SUMMARY pastes the totals.
</acceptance_criteria>
