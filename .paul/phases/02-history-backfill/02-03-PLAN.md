<objective>
## Goal
Push history_start from 2020-03-26 back to 2017-10-12 using the FAA's own NASR subscription files, as preserved by the Internet Archive (Wayback Machine).

## Purpose
Operator: "Use the archives to fill in as much history as you can then attempt to locate another histoical source to fill in more history." cv-aviation's logbook data goes back to 2019-09, before the FAA's archive (2020-03-26) begins.

## Output
A Wayback source for cycles the FAA no longer serves, the re-run seed (still unpublished) with a new pin, tests, and the report. Nothing is published.
</objective>

<context>
Discovery, 2026-11-19 (read-only CDX queries on web.archive.org):
- Wayback holds `nfdc.faa.gov/webContent/28DaySub/28DaySubscription_Effective_D.zip` for every 28-day cycle from **2017-10-12 to 2020-03-26, with no gaps** (33 cycles; 32 before the FAA archive). The next cycle back, 2017-09-14, is missing. Captures were made 2020-10 and 2021-03.
- `web.archive.org/web/<timestamp>id_/<url>` returns the original bytes and honours Range (206), so the existing range reader works.
- Pre-check of AC-1, done at planning: the Wayback copy (capture 20210325204726) and the FAA copy of 2020-03-26 are both 118,864,479 bytes with sha256 2ddb00d5d6271849e06e13856cc7daeb3ad06486892744ea796c148f7712709d. Apply re-checks it.
- Licence: these are FAA works (public domain). The Archive is only the carrier.
- OurAirports before 2021-11 (Wayback captures of ourairports.com/data/airports.csv) is not in this plan. It would only add non-NASR airports, and its captures are sparse. It can be a later plan if cv-aviation needs it.

</context>

<acceptance_criteria>
## AC-1: Carrier is faithful
The Wayback copy of 2020-03-26 is byte-identical (sha256) to the FAA's copy of the same cycle. If it isn't, stop: the plan does not proceed on Wayback data.

## AC-2: Source and provenance
`backfill` uses the FAA URL when it serves the cycle, else the Wayback capture from the CDX index (newest 200 capture of that exact URL). Each cycle's cache meta records the source (faa|wayback), the capture timestamp, the URL and the sha256 of the bytes read, and `backfill_sources` in the seed says which cycles came from the Archive. All zip member CRCs must check.

<!-- sqwkd-added --> If the CDX index holds more than one 200 capture of a cycle URL with different sha256 (an FAA re-post), the SUMMARY lists them and says which was used.

## AC-3: Format holds
The 2017-10-12 … 2020-02-27 files parse with the format-a layout. Any cycle where the APT.txt record length or field layout differs is refused, not guessed. Report per-cycle record counts; the anomaly guard (2%) applies, with no new allowlist entries unless explained in the SUMMARY.

## AC-4: Re-run seed
`backfill --from 2017-10-12 --to 2026-10-01` produces a seed that passes check_identity and check_chain at every step, is reproduced byte-identically by a second run, and still keeps PBI→DJT on one id. identity/seed.json is re-pinned (published stays false). history_start becomes 2017-10-12. The 2026-10-29 build from the new seed passes verify --previous.

## AC-5: Report
SUMMARY: cycles by source, ids minted at the first cycle, aliases, IATA multi-holder counts for the new cycles, and the new seed sha256. cv-aviation and sqwkd are told that ids are re-minted (nothing was published, so no consumer holds the old ones).
</acceptance_criteria>
