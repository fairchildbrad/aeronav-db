<acceptance_criteria>
## AC-1: Cache audit (sqwkd 1)
Per cycle in backfill_sources: which guards and parsers ran on fresh bytes and which ran only on rows parsed before a later guard, for every guard listed in the context. Compare with P1.

## AC-2: Layout census (sqwkd 2)
For all 66 format-a cycles: the set of actual record lengths, the stated RECORD LENGTH, and a pass/fail for each LEGACY_FIELDS entry. Every mismatch is listed by cycle. Compare with P2 and P3.

## AC-3: Guard
`legacy_apt_rows` takes the archive's `Layout_Data/apt_rf.txt`. A record is accepted only when:
- **(a)** its length equals the RECORD LENGTH that file states, and
- **(b)** each LEGACY_FIELDS entry appears in that file with the same start, length and field name.

A missing apt_rf.txt is **refused**. There is no hard-coded fallback unless AC-2 shows a cycle that needs one, and in that case the cycle is named and the fallback comes back to sqwkd. If AC-2 finds a layout file a cycle ahead of its records (2021-04-22), the guard rule comes back to sqwkd with the census, before APPLY continues. It is not tuned.

## AC-4: Tests (sqwkd 4)
A 1531 layout with matching fields is accepted. A moved field is refused. A stated length different from the actual length is refused. A missing apt_rf.txt is refused. ruff and the full pytest suite pass.

## AC-5: Reproduction (sqwkd 5)
Cold cache, the code that built e92fa5fe plus the 02-04 guard. The base is aa2e206, the backfill code at seed time; the 01-03 and 01-04 identity changes are excluded, since they change the output by design. The result must match e92fa5fe **byte for byte**. If it doesn't, report the first differing table and row and stop. A near match is not accepted. That seed becomes 01-04's control.

## AC-6: Record (sqwkd 6)
The SUMMARY states that e92fa5fe could not be reproduced from a cold cache from 76d0feb until 02-04, and that the 02-01/02-02 reviews missed it.
