## AC-1: Phase 3 done (the release gate)
Recorded in ROADMAP Phase 3 and checked by a new `python -m aeronav_db.tz gate <db>`, which exits non-zero when the gate fails. Phase 3 is done when, on a build from the seed:
1. **Every region is classified.** In each of the 33 multi-zone countries except AQ, every ISO 3166-2 region holding a present airport has either a cited region rule or is listed in partial_regions.csv (AC-2). Measurably: no present airport has tz_unplaced = multi_zone_country, except in AQ.
2. **Scheduled airports are placed.** Every present airport with OurAirports scheduled_service = yes has a tz, or is listed by airport_id in `identity/tz/unplaced_by_design.csv` with a reason. The reasons allowed are: a cited source_conflict; no ISO region in the source (`-U-A`); AQ; or no official source places it, with what was searched.
3. Every rule, sub-region row and override cites its source. The SUMMARY of each plan names the countries for which no independent offset check exists.

Left NULL by design, and documented in the README:
- Antarctica (AQ). Station time is chosen by each station's operator, and ISO 3166-2 has no regions there.
- Non-scheduled airports in partial regions that no sub-region row covers. They report no_county_match.
- Cited source conflicts.

## AC-2: Per-region partial guard (refines T3; no rule loosened)
`identity/tz/partial_regions.csv` has the columns `iso_country, region, zones, tzdata_quote`. It lists every region that a zone1970.tab comment marks as most/except/part, or that two zones' comments both name (for example CA-BC, which Vancouver, Dawson_Creek, Fort_Nelson, Edmonton and Phoenix all name).
- A region rule for a listed region is a load error.
- A listed region must be SPLIT in rules.csv.
- The load fails if a zone1970.tab comment contains most, except or part and none of the regions it names is listed. This keeps the list complete as tzdata changes.

The per-zone comment heuristic is removed. MX-BCS and MX-SIN may then take region rules; MX-NAY may not.

## AC-3: Sub-region key outside the US
For a non-US airport, `placement_inputs` passes the OurAirports `municipality` (upper-case, trimmed) in the county slot. US airports keep the NASR COUNTY_NAME, and a US airport known only from OurAirports gets no sub-region key.
- Sub-region rows reuse rules.csv `(country, region, county)`. Each row's note cites the statute or decree naming that place.
- An airport in a SPLIT region whose municipality has no row stays NULL, no_county_match. No new reason code and no DDL change.
- The README says that outside the US the third key is the OurAirports municipality, which is free text and not authoritative. A misspelt or missing municipality leaves the airport NULL; it never misplaces it.
- An airport position more than 1° of longitude outside the span of the other airports given the same sub-region row is reported for review. This is a lint only; it does not place anything.

## AC-3a: Municipality lint blocks unify (M1)
OurAirports `municipality` is usually the city served, not the place the airport sits in. Near a zone line that misplaces an airport rather than leaving it NULL. So the AC-3 lint blocks unify:
- **Flagged:** an airport more than 1° of longitude outside its row's span. Also any airport placed by a municipality row that lies within about 0.5° of longitude of a statutory boundary meridian named in the sources (for example Ontario's 90°W).
- **Resolved:** every flagged airport is either confirmed (the SUMMARY says why its position fits the row), placed by a cited override, or set NULL with no_county_match.
- **Reported:** the SUMMARY gives the number flagged and how each was resolved.

The README's NULL statement is corrected to say a municipality row can misplace an airport, and that this lint is the guard.

## AC-4: Mexico
- Source: Ley del Sistema de Horario en los Estados Unidos Mexicanos (DOF 2022-10-28) and its border-municipality reform (DOF 2022-11-30), which list states and municipalities per time zone. Each note cites the article.
- Whole states get region rules.
- CHH, COA, NLE, TAM and NAY are partial (AC-2). Their scheduled airports are placed by municipality rows that cite the article naming the municipality.
- Canaries: MMUN America/Cancun, MMMX America/Mexico_City, MMSD America/Mazatlan, MMMZ America/Mazatlan, MMOX (OAX) and MMQT (QRO) America/Mexico_City (cv-aviation note 1).

## AC-5: Canada
- Sources: each province's and territory's time legislation, and the National Research Council's published statement of Canadian time zones. Each note cites the act and section, or the NRC page.
- AB, MB, NB, PE and others that no comment marks as partial get region rules.
- The split provinces and territories (AC-2) are placed by municipality rows. Example: Ontario's Time Act places west of 90°W on Central time, and named communities such as Atikokan are exceptions. A row is written only where a cited source names the place, its district, or a rule (meridian, rest-of-province) that the municipality's location satisfies. A municipality near a boundary named by the rule is left NULL (cv-aviation note 2). This is a citation basis, not placement from position; AC-3a's lint still applies.
- Canaries: CYYC (Calgary) America/Edmonton (region rule); CYYZ America/Toronto, CYVR America/Vancouver and CYHZ America/Halifax (municipality rows; NS is partial, with Cape Breton on Glace_Bay).
- The 43 CA airports with no ISO region (`CA-U-A`) stay no_region unless an override cites a source.
