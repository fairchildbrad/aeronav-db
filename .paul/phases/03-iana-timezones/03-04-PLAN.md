## AC-1: Gate
On a build from the seed, `tz gate` prints no line for any country except US. The SUMMARY gives, per country: placed, NULL by reason, scheduled placed, and scheduled in unplaced_by_design with reasons.

## AC-2: zone_regions covers every multi-zone country; R2 carried from 03-03
- **Mapping:** every country with two or more zone1970 zones has zone_regions rows. The load fails when one doesn't, except AQ (NULL by design). The exemption is listed in code and tested.
- **R2 (carried from 03-03, verbatim):** "a zone with no rows for country X is allowed only if zone_regions maps it to a region of another country listed for it in zone1970; test included".
  - This replaces 03-03's narrower rule ("zone1970 also lists it for another country").
  - Effect: RU's empty Europe/Simferopol row is valid only because UA maps Simferopol to UA-43.
  - A test shows a shared zone that no other country maps still fails.
- **Exception for countries without ISO 3166-2 subdivisions** (expected only TF): rows with empty regions, each with a source. Where the country has no airports, they're tested at load only.
- The SUMMARY reports every region the check flags.

## AC-3: placement inputs for retired and user-assigned codes
- **AN:** `placement_inputs` applies the same AN→BQ/CW/SX successor mapping as identity, using OurAirports' country when it is one of the successors. Test included. TNCE and TNCM then place through the existing single-zone rules (BQ, SX).
- **XK:** BKPR gets an airport-keyed override → Europe/Belgrade. The note quotes tzdata europe's Belgrade heading, which lists Kosovo, and states it takes no position on status. No XK rules row: the loader correctly refuses a country that isn't in zone1970.
- No change to the identity's iso_country values. That is a Phase 1 concern, so it's raised in the SUMMARY only.
