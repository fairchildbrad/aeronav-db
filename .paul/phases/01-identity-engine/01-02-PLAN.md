## Schema 3 DDL (for cv-aviation review)

```sql
-- One row per airport ever seen. Rows are never deleted.
CREATE TABLE airport_identity (
    airport_id       TEXT PRIMARY KEY COLLATE NOCASE
                     CHECK (airport_id GLOB 'AP[0-9][0-9][0-9][0-9][0-9][0-9][0-9]'),
    nasr_site_no     TEXT,              -- e.g. '03555.'; attribute, not identity
    nasr_site_type   TEXT,              -- A C G B U H
    ourairports_id   TEXT,              -- e.g. '3766'; attribute, not identity
    name             TEXT,
    lat              REAL NOT NULL,     -- as last seen
    lon              REAL NOT NULL,
    kind             TEXT,
    iso_country      TEXT,
    source_status    TEXT NOT NULL,     -- operational | closed_indefinitely |
                                        -- closed_permanently | closed  (only when a source says so)
    first_cycle      TEXT NOT NULL,     -- YYYY-MM-DD, effective date of first appearance
    last_seen_cycle  TEXT NOT NULL,
    in_current_cycle INTEGER NOT NULL,  -- 1 if present in this file's cycle
    match_basis      TEXT NOT NULL,     -- basis of the MOST RECENT match: minted | nasr_site |
                                        -- nasr_site_number | faa_lid_within_1nm | ourairports_id
    tz               TEXT,              -- IANA zone, e.g. 'America/New_York'. NULL until Phase 3
    tz_basis         TEXT               -- country | region | override. NULL until Phase 3
);

-- Which code an airport held, and when. Closed rows never change.
CREATE TABLE airport_codes (
    airport_id     TEXT NOT NULL COLLATE NOCASE REFERENCES airport_identity(airport_id),
    scheme         TEXT NOT NULL CHECK (scheme IN ('faa', 'icao', 'iata')),
    code           TEXT NOT NULL COLLATE NOCASE,
    source         TEXT NOT NULL,       -- nasr | ourairports
    effective_date TEXT NOT NULL,       -- AIRAC cycle date the code took effect
    valid_to       TEXT,                -- exclusive; NULL = still held
    PRIMARY KEY (airport_id, scheme, code, effective_date)
);
CREATE INDEX airport_codes_by_code ON airport_codes (scheme, code, effective_date);

-- Presence in the dataset. A gap means "absent from these cycles", not "closed".
CREATE TABLE airport_presence (
    airport_id     TEXT NOT NULL COLLATE NOCASE REFERENCES airport_identity(airport_id),
    effective_date TEXT NOT NULL,
    valid_to       TEXT,                -- exclusive; NULL = present now
    PRIMARY KEY (airport_id, effective_date)
);

-- Converged identities. Always one hop: airport_id is never itself an alias_id.
CREATE TABLE airport_aliases (
    alias_id       TEXT PRIMARY KEY COLLATE NOCASE,
    airport_id     TEXT NOT NULL COLLATE NOCASE REFERENCES airport_identity(airport_id),
    effective_date TEXT NOT NULL,
    reason         TEXT NOT NULL        -- converged
);

-- Existing current-cycle lookup table gains the permanent id.
-- airports(code PK, lat, lon, name, kind, code_type, source, airport_id NOT NULL)
-- code_type fix: a NASR identifier is labelled 'faa', never guessed as 'iata'.

-- metadata gains: airport_id_next (counter), history_start (first cycle in the chain),
--   previous_cycle and previous_db_sha256 (lineage; empty on a bootstrap).
```

Example lookup, "which airport did IATA PBI mean on 2026-08-01":
```sql
SELECT COALESCE(a.airport_id, c.airport_id) AS airport_id
FROM airport_codes c LEFT JOIN airport_aliases a ON a.alias_id = c.airport_id
WHERE c.scheme = 'iata' AND c.code = 'pbi'
  AND c.effective_date <= '2026-08-01'
  AND (c.valid_to IS NULL OR '2026-08-01' < c.valid_to);
```
A date before `history_start` has no answer: history only begins where the chain begins. IATA lookups may return more than one airport (worldwide collisions); disambiguate by position.

## AC-1: Schema 3 written
Given a build
When it completes
Then the four tables above exist with those constraints, every `airports` row has an airport_id present in airport_identity, schema_version = 3, and metadata holds airport_id_next and history_start.

## AC-2: Chained build
Given `--previous-db PREV` (a schema-3 file)
When cycle N is built
Then identity state is loaded from PREV and advanced through `apply_cycle`, and history_start is carried over.
Given no `--previous-db`
Then the build refuses unless `--bootstrap` is passed, so an accidental re-mint is impossible.
Given a PREV whose cycle is ≥ N
Then the build fails.

## AC-3: Observations from both sources
NASR observations include every APT_BASE row with coordinates, including CI/CP, mapped to closed_indefinitely and closed_permanently. OurAirports observations use the same rows as the airports layer, with type 'closed' mapped to closed. The current `airports` merge output is unchanged apart from the new airport_id column and the code_type fix.

## AC-4: Verify guarantees
Given `verify NEW --previous PREV`
Then it fails if any of these hold:
- a PREV airport_id is missing from NEW
- a closed PREV interval (codes or presence) differs or is missing
- an open PREV interval was closed at a date other than NEW's cycle
- an alias target is itself an alias
- an id breaks the AP+7 shape
- airport_id_next ≤ the highest id
Without `--previous`, it still checks the shape, one-hop aliases, the airports→identity link, and a canary: IATA DJT and ICAO KDJT resolve to the same airport_id.

## AC-6: One holder per FAA/ICAO code (sqwkd A1)
Rule: an open code interval closes at the first cycle in which its holder no longer holds that code, whether the holder changed code, the code moved to another airport, or the holder is absent. An absent airport holds no codes. "The source still lists the code" can only mean that another source record holds it, and that record is either the same airport (it attaches) or a different one (it opens its own interval).
If an airport stays present only through its attached OurAirports row, that row's codes remain. An interval whose code is still held stays open, even if the source changes.
Attachment gate (fix for a measured defect): an OurAirports row attaches to a NASR record when they share a code and are within SAME_AIRPORT_NM, and either the OurAirports country is in NASR_JURISDICTION or it equals the NASR record's COUNTRY_CODE. The 2026-10-29 data has 112 non-US fields (CA 67, BS 25, FM 5, TC 4, MH 3, and others) listed by both NASR and OurAirports, 0–2 nm apart, that would otherwise be two ids with the same open ICAO interval.
Verify, with and without `--previous`: at most one open interval per (scheme, code) for faa and icao, and no two overlapping intervals for the same faa/icao code. It reports, without failing, the count of IATA codes held by more than one present airport (cv-aviation's uniqueness request). A collision found in real data fails the build. It is never resolved silently.

## AC-7: Convergence leaves history in place (sqwkd A2)
When X becomes an alias of Y at cycle N, X's airport_codes and airport_presence rows stay under X: closed rows are unchanged, and open rows close at N. Y opens rows from N for whatever it now holds. `verify --previous` passes across a convergence. Test: converge across two cycles, build both files, and verify --previous exits 0.

<!-- audit-added -->
## AC-8: The chain input is validated and the output is never half-written (audit)
Given `--previous-db PREV`
Then the build fails before it reads any source if any of these hold: PREV is not schema_version 3; PREV resolves to the same file as the output (write_database unlinks the output first, so this would destroy the history it extends); `--bootstrap` was passed as well; PREV's airport_id_next ≤ its highest id; or PREV fails the AC-4/AC-6 invariants without `--previous`.
The identity state is loaded completely into memory before anything is written. The database is written to a temporary file next to the output and renamed into place only after the identity invariants pass on the new state. A failed build leaves no output file and exits non-zero.
Every `airports` row maps to exactly one airport_id. An unmapped row fails the build. It never gets a NULL, a fresh mint, or a guess.

<!-- audit-added -->
## AC-9: Lineage is recorded and the build is reproducible (audit)
metadata gains previous_cycle and previous_db_sha256 (empty on a bootstrap), so every file names the exact parent it was chained from. sqwkd's Phase 2 manifest check compares against these.
dump_state(load_state(PREV)) reproduces PREV's four identity tables row for row (round-trip test). Building the same cycle from the same PREV and sources twice gives identical identity tables.
Verify checks referential integrity explicitly, since SQLite does not enforce foreign keys by default: every airport_codes, airport_presence and airport_aliases row names an airport_identity row. in_current_cycle = 1 exactly when the identity has an open presence row. It warns, without failing, when previous_cycle is not 28 days before the cycle, which shows a skipped cycle.

## AC-5: Documented
The README gains an "Airport identity and history" section with the DDL semantics, the lookup query, the guarantees, and "absent ≠ closed".
